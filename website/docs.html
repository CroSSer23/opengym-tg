Self-host with Docker

Docker with Compose is the only requirement. The frontend builds inside the image, so you do not need Node installed.

git clone https://github.com/CroSSer23/opengym-tg
cd opengym-tg
cp .env.example .env
docker compose up -d

Open http://localhost:8080 and tap Create profile. The first run downloads the exercise images and animations once, about 140 MB, into ./media.

Your data lives in ./data: db.json holds profiles and public passkeys, state-<user>.json holds one person's plan, workouts and weight, and secret signs the session cookies. Passkey private keys never reach the server; they stay in your phone's secure hardware.

Putting it behind HTTPS

Two things need a real domain: passkeys, which browsers bind to a hostname and refuse over plain HTTP, and the Telegram Mini App, which Telegram will not open without HTTPS. Point a reverse proxy at the web container and set:

RP_ID=gym.example.com
ORIGIN=https://gym.example.com
Most sign-in problems on a self-hosted instance are an RP_ID or ORIGIN that does not exactly match the address in the browser bar.

Run it inside Telegram

Off unless you set a bot token. With none set, no Telegram route answers and no Telegram UI renders anywhere in the app.

  1. Message @BotFather and send /newbot. Keep the token it gives you.
  2. Put it in .env: 
    TELEGRAM_BOT_TOKEN=8012345678:AAH...
  3. docker compose up -d, then find your bot and send /start.

That is the whole configuration. On boot the container introduces itself to Telegram, sets the bot's command list, and installs the menu button that opens your instance.

Already have a passkey profile? Sign in on the web first, then open the Mini App and use Settings → Telegram → Link this Telegram account, so both doors reach one profile instead of creating a second.

The bot token is a credential. Anyone holding it can mint a valid launch for any account and walk into any profile on the instance. Treat it like the session secret.

Point the AI Coach at your own endpoint

The Coach is off until an admin enables it, and each profile consents separately before any of its data is used. To be an admin, register your profile, find your id in ./data/db.json, and list it:

ADMIN_UIDS=youruserid

Then Settings → Admin → AI Coach, choose OpenAI-compatible endpoint, and fill in three fields:

  • Endpoint the base URL, for example https://api.openai.com/v1 or http://ollama.lan:11434/v1. A bare host gets /v1 appended.
  • Model required. A raw endpoint has no default to fall back on.
  • Credential an API key, unless the endpoint is on your own network and wants none.

Model choice matters more here than with a hosted product, because nobody is picking a sensible default for you. The Coach asks for one structured JSON object over a long prompt; small local models tend to fail the validator rather than produce a bad plan, which is the right failure but still a failure.

What leaves your server is an allowlist, built field by field: your plan, the logged sets in the review window, your weigh-ins, your intake answers and your unit and language. Never your name, your user id, passkey material or anyone else's anything.

Bring your history with you

Settings → Import reads exports from FitNotes, Strong and Hevy, including the RPE they record, and body weight straight out of an Apple Health export. Exercise names are matched against the library; anything unrecognised becomes one of your own exercises, so nothing in the file is dropped.

Backups

Back up ./data and you have backed up everything. There is also a one-tap JSON export per profile in Settings, which is the right thing for moving one person between instances.

Restoring ./data without its secret file signs everyone out and makes a stored Coach credential unreadable. Copy the whole folder.

FAQ

Is there a mobile app to download?

Not from this fork. The codebase still contains the Capacitor projects upstream uses to build a standalone Android app, and you can build one yourself from frontend/android, but no signed build is published here. On a phone, the self-hosted instance installs as a home-screen app, and inside Telegram it is a Mini App.

What data does it collect?

None. There is no analytics, no telemetry and no phone-home. The only outbound requests are the exercise media download on first run, and, if you turn them on, your own AI endpoint and your own Telegram bot.

Is it really free?

AGPL-3.0. Free to run, modify and share. If you run a modified version as a network service you have to offer that version's source under the same licence, which is the point of the licence rather than a footnote.

Where does the exercise database come from?

From hasaneyldrm/exercises-dataset, under its own terms. The images and animations are fetched at first run rather than shipped in the repository.

Who wrote this?

Most of it is not this fork's work. See About.
